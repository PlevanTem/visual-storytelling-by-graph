# 评测方法

## 分开执行材料和答案

- `evals/requests/*.md`：用户请求与数据路径。
- `evals/fixtures/*.json`：固定合成数据与必要元数据。
- `evals/cases.json`：评审事实、设计不变量、可接受替代与失败条件。

独立执行者不读答案。`examples/plans.json` 是作者方案，`examples/charts/` 是示范产物，都不是泛化能力证据。

## 对照评测 [R09]

固定模型、工具、数据、任务、媒介与预算，对比无 Skill 和使用 Skill。必要时重复，记录版本与随机性。评审尽量隐藏条件。

硬失败：错误分母、伪配对、捏造数据、因果或路径、主要输出不可用。软评审：任务覆盖、比较精度、重要信息、可读性、交互成本和视觉层级；用观察解释，不凑未经校准的总分。

真实目标读者回答预定义问题；准确性、时间、误读与美观评价分开记录。用未参与修订的案例复查，避免把答案写进规则。

独立 Agent 检查行为和适配，仍不等于真实读者实验。
